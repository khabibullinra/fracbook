# Роли участников

В репо нет Git-уровневых ограничений «по умолчанию» — роли логические, для
координации. Технические границы (PR-only в `dev` и `master`, push в `pages`
только через CI) настраиваются в UI GitVerse — см. `PUBLISHING.md` →
«Защита веток».

Архитектурное обоснование workflow — в `docs/decisions/0003-publication-workflow.md`.

## Преподаватель-редактор (один)

- Отвечает за содержание `book/`.
- Принимает PR в `book/`.
- Делает релизные PR `dev → master`.
- Прямой push в `master` через UI (обход PR) — допустим в экстренных
  случаях (например, опечатка на опубликованной странице). Локально перед
  push прогоняется тройка `pytest -q` + `ruff check src tests` +
  `quarto render book/`.
- Имеет branch protection override для `master`.
- **Не пушит в `pages` руками** — это делает CI после мержа в `master`.

## Преподаватели-разработчики (несколько)

- Развивают `src/fracbook/`, ведут `models/`.
- Принимают PR в `src/` и `models/`.
- Участвуют в обсуждении архитектуры через ADR в `docs/decisions/`.
- Имеют branch protection override для `dev` (мержут PR).

## Студенты

Студенты **не имеют прямого доступа** к основному репо. Работают через
форк — пошагово в `docs/student-workflow.md`.

Кратко:

- Форк `khabibullinra/fracbook` в свой аккаунт GitVerse.
- `git clone` своего форка, ветка `student/<ник>/<короткое-описание>`.
- Работа, коммиты, push **в свой форк**.
- PR из своего форка в `khabibullinra/fracbook:dev`.
- Ревью от преподавателя, доработки, мерж.

Типичные задачи студентов:

- Материалы в `book/lecture-NN-*.qmd` (заметки, разборы, дополнительные
  примеры).
- Ноутбуки в `notebooks/drafts/`.
- Помощь с переводом англоязычных терминов в `book/CONTRIBUTING.md`
  (словарь).

## Все участники

Перед PR прогоняют локально:

```bash
pytest -q
ruff check src tests
quarto render book/
```

(Для студентов последний пункт — опционально: `pytest` + `ruff` достаточно,
рендер упадёт в CI при необходимости. Но рекомендуется — экономит время
ревью.)

### Общие соглашения

- Используют `.venv` в корне проекта. Никаких системных установок `fracbook`.
- Перед коммитом убеждаются, что в `master`/`dev` не попадут:
  - `.venv/`, `_book/`, `_freeze/`, `_site/`, `.ipynb_checkpoints/`;
  - бинарь симуляторов (`.geos`, `.unrst`, `.EGRID`, `.INIT`, логи);
  - крупные (>10 МБ) выходные данные ноутбуков;
  - артефакты `quarto preview` (`*.quarto_ipynb` и `*.quarto_ipynb_*`).

Подробные соглашения по стилю кода и книги — в `book/CONTRIBUTING.md`.
Соглашения по ноутбукам — в `notebooks/README.md`.
