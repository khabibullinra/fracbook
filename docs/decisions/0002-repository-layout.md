# ADR-0002: Раскладка репозитория

## Статус

Принято, июль 2026.

## Контекст

В репо будут: библиотека расчётов, книга, экспериментальные ноутбуки, модели
гидродинамических симуляторов, документация репо. Эти зоны имеют разную аудиторию
и разные темпы изменений.

Нужно:

- изолировать расчётную библиотеку, чтобы её можно было переиспользовать вне книги;
- дать ноутбукам и моделям собственные зоны без пересечения с основной книгой;
- оставить место для расширения (новые симуляторы, новые типы артефактов).

## Решение

```
fracbook/
├── src/fracbook/         # Python-пакет, src-layout; тесты в tests/
├── tests/                # pytest для src/fracbook/
├── book/                 # Quarto-книга (публикуется в Pages)
├── notebooks/            # Quarto-проект экспериментов (drafts/reviewed/scratch)
├── models/               # модели гидродинамических симуляторов
│   └── <simulator>/<NN-slug>/
├── docs/                 # документация репо, ADR
├── tools/                # POSIX-скрипты поддержки (publish-pages.sh)
└── .gitverse/workflows/  # CI smoke-test
```

## Последствия

- `src/fracbook/` изолирован; ставится отдельно (`pip install -e .[dev]`) и импортируется
  из любой подсистемы (книга, ноутбуки, модели — для пред-/пост-обработки).
- `book/` и `notebooks/` — независимые Quarto-проекты. Собираются и публикуются раздельно.
- `models/` хранит только текстовые исходники (`.data`, `include`-секции) и скрипты
  воспроизведения. Бинарные артефакты симуляторов — в `.gitignore`.
- `docs/` отделён от `book/`: `book/` — продукт для студентов, `docs/` — про работу
  над продуктом (роли, ADR, конвенции для контрибьюторов).
- Расширение под новые симуляторы — завести `models/<sim>/`, скопировать `_template/`.
- Расширение под новые типы артефактов — завести новую подпапку в корне по аналогии
  с `models/` или `notebooks/`.

## Альтернативы, которые отклонили

- **Всё в одном Quarto-проекте** — смешивает продукт и инфраструктуру, ломает переиспользование `fracbook`.
- **Монорепо с подпакетами** (`packages/book`, `packages/lib`) — лишний слой для проекта такого размера.
- **Подмодули git** для `models/` — усложняет работу, не даёт выигрыша на текущем масштабе.
