# Соглашения по оформлению книги

Это соглашения для авторов и соавторов методички. Соблюдение — обязательная часть процесса ревью.

## Язык и стиль

- **Язык — русский.** Включая подписи, оглавления, заголовки, alt-текст изображений.
- **Терминология** — русские эквиваленты по словарю ниже. Если термина нет в словаре — добавить в словарь вместе с новым материалом.
- **Машинный перевод недопустим.** Если цитируется англоязычный источник — цитата на английском, окружающий текст на русском.
- **Лица и обращение** — нейтрально-безличное («полагают», «считается», «принимается»). Не «мы считаем», не «давайте рассмотрим».

## Словарь терминов (начальный)

При добавлении нового термина — ставить в алфавитный порядок.

| Английский | Русский | Комментарий |
|---|---|---|
| fracture half-length | полудлина трещины | $x_f$ |
| fracture conductivity | проводимость трещины | $k_f w$ |
| dimensionless fracture conductivity | безразмерная проводимость трещины | $C_{fD}$ |
| dimensionless productivity index | безразмерный индекс продуктивности | $J_D$ |
| skin factor | скин-фактор | $S$ |
| propped length | длина проппантной части трещины | $x_{fp}$ |
| leak-off coefficient | коэффициент утечки | $C_L$ |
| net pressure | давление в трещине за вычетом закрывающего | $\Delta p$ |

Дополнения в словарь — отдельным коммитом с сообщением вида `glossary: add <термин>`.

## Математика

- Блочные формулы — LaTeX в `$$ … $$`, нумерация `equation: true` в YAML-шапке `.qmd` (для глав с уравнениями).
- Инлайн-формулы — `$ … $`.
- Соглашения по шрифтам и индексам — единые по книге:
  - скаляры — курсив;
  - векторы — жирный курсив;
  - индексы и показатели степеней — прямой шрифт внутри курсива.
- Список обозначений — в `book/appendices/symbols.qmd` (создаётся при необходимости).

## Графики

Все рисунки — из Python-чанков (matplotlib/plotly), не из внешних файлов без необходимости.

- **Подписи осей** — на русском, с указанием единиц в скобках: `Давление, МПа`, `Длина, м`, `Дебит, м³/сут`.
- **Легенда** — на русском.
- **Шрифт** — без засечек (sans-serif), размер ≥ 10 pt для печати.
- **Формат** — SVG для векторной графики, PNG ≥ 150 dpi для растровой.
- **Файлы** — `book/images/<chapter-slug>/<descriptive-name>.svg`.

## Библиография

- BibTeX-файл — `book/references.bib`.
- Цитирование — `[@citekey]`, стиль — на усмотрение автора, единый по главе.
- Источники — только рецензируемые публикации, монографии, отраслевые стандарты. Википедия и популярные сайты — не источник.

## Code chunks (`.qmd`)

- Язык по умолчанию — Python. R/Julia — только если оговорено отдельно.
- **Никаких «голых» численных расчётов** в чанках. Любой расчёт — через `fracbook`:
  ```python
  # ✓ правильно
  from fracbook import pkn_half_length
  xf = pkn_half_length(q=4.0, t=60, ...)
  # ✗ неправильно
  xf = 0.5 * (4.0 * 60) ** 0.5
  ```
- Импорты — в начале чанка, без `import` посреди кода.
- Размер чанка — до 30 строк; больше — разбивать или выносить в `book/scripts/`.
- Длинные скрипты — `book/scripts/<name>.py`, импортируются явно.

## Python: окружение

**`venv` в корне проекта — обязателен для всех участников.** Это не рекомендация, а соглашение.

- Никаких системных `pip install fracbook` или `pip install --user`. Только `.venv`.
- Перед `quarto render` / `quarto preview` / запуском pytest — `.venv` должен быть активирован (или в Positron выбран как интерпретатор).
- Quarto использует Python из `PATH` → с активированным `.venv` чанки `python` подхватят пакет автоматически.

Подробности и команды активации для каждой ОС — в `book/PUBLISHING.md`.

## Тесты перед PR

Перед открытием PR в `master` (или перед передачей материала преподавателю-редактору) — прогнать локально:

```bash
pytest -q              # все тесты зелёные
ruff check src tests   # линтер чистый
quarto render book/    # .qmd без синтаксических ошибок
```

Команды работают одинаково на Linux, macOS и Windows.

Если что-то падает — чинить в своей ветке до ревью. Это экономит время преподавателя.

## Технические соглашения

- **Кодировка файлов — UTF-8 без BOM.**
- **Концы строк — LF** (зафиксировано в `.gitattributes`).
- **Пути в `.qmd` — forward-slash** (`images/scheme.png`), даже в Windows. Обратный слэш ломает рендер на части конфигураций.
- **Кодировка изображений — SVG предпочтительна**, PNG ≥ 150 dpi допустимо, JPEG — только для фотографий керна/оборудования.
