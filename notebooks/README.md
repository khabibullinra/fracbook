# Ноутбуки с экспериментами

`notebooks/` — отдельный Quarto-проект для исследовательских расчётов, прототипов и
проверки гипотез. Не путать с основной книгой (`book/`).

## Жизненный цикл

| Папка | Назначение | Попадает в `book/`? |
|---|---|---|
| `drafts/` | Рабочие материалы. Любой участник может создать. | Нет |
| `reviewed/` | Прошли ревью преподавателя-разработчика. | Да — можно ссылаться |
| `scratch/` | Черновики «на выброс». Папка gitignored. | Нет |

## Соглашения по именованию

`YYYY-MM-DD-<автор>-<тема>.ipynb`

- `<автор>` — латиницей, без пробелов (например, `ivanov`, `khabibullin`).
- `<тема>` — короткое описание в kebab-case.

Пример: `2026-07-15-ivanov-pkn-sensitivity.ipynb`.

## Содержимое ноутбука

- Python-чанки — только вызовы `fracbook` и визуализация. Новая математика — в `src/fracbook/`.
- Импорты — в начале первого чанка.
- Размер ноутбука — до ~50 ячеек; больше — разбить или вынести тяжёлые части в модуль `fracbook`.
- Большие (>10 МБ) выходные данные — регенерировать, не коммитить.

## Локальный запуск

```bash
# С активированным .venv в корне проекта:
quarto preview notebooks/   # рендерит и показывает в браузере
jupyter lab notebooks/      # альтернатива: классический интерфейс Jupyter
```

В Positron (Windows у студентов): команда **Quarto: Preview** или **Jupyter: Open Notebook**.

## Перенос в `book/`

Когда ноутбук дорос до оглавления методички:

1. Уточнить математику, вынести в `src/fracbook/` (если ещё не вынесена).
2. Написать `.qmd`-главу в `book/chapters/`, использующую те же вызовы `fracbook`.
3. Из ноутбука убрать или перенести в `reviewed/` (как референс).

Преподаватель-редактор принимает решение о переносе.

## Чего не делать в ноутбуках

- Не дублировать формулы из книги — дать ссылку на `book/chapters/...`.
- Не сохранять бинарные артефакты (`.geos`, `.unrst`, логи симуляторов) — для них есть `models/`.
- Не добавлять специфичные CI/CD-конфиги — для этого есть `.gitverse/workflows/`.
